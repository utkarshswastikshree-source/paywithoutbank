📌 Project Overview

PayWithoutBank is a backend application built with Java and Spring Boot to demonstrate digital wallet operations, REST API development, database persistence, and safe handling of concurrent money transfers.

The project focuses on maintaining consistent wallet balances when multiple transfer requests execute simultaneously.

✨ Features

- Create users through REST APIs.
- Deposit money into wallets.
- Transfer money between wallets.
- Retrieve wallet balances.
- Store application data in PostgreSQL.
- Use Spring Data JPA and Hibernate for persistence.
- Apply pessimistic locking to protect wallet updates from conflicting concurrent transactions.
- Use transactional processing to maintain database consistency.
- Test concurrent transfer behaviour using JUnit 5.
- Explore and test endpoints through Swagger UI.

🏗️ Application Architecture

The application follows a layered backend architecture.

1. Controller Layer: Receives HTTP requests and returns API responses.
2. Service Layer: Implements wallet operations and business logic.
3. Repository Layer: Interacts with the database through Spring Data JPA.
4. Entity Layer: Represents application data such as users, wallets, and transactions.
5. Database Layer: PostgreSQL stores persistent application data.

Request Flow

"Client → Controller → Service → Repository → PostgreSQL"

The response then returns to the client through the controller.

🔒 Concurrency Handling

The Problem: Race Conditions

When multiple requests access and update the same wallet concurrently, they may read outdated balances or overwrite each other's updates.

This can lead to incorrect balances if the operations are not properly synchronized.

The Solution

The project uses pessimistic write locking and transactional processing.

Pessimistic Locking

The wallet repository uses JPA locking:

@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("SELECT w FROM Wallet w WHERE w.id = :id")
Optional<Wallet> findByIdWithLock(@Param("id") Long id);

This requests a write lock on the selected wallet row, helping prevent conflicting transactions from updating the same wallet simultaneously.

Transaction Management

"@Transactional" groups related database operations into a transaction. If a qualifying failure occurs, the transaction can be rolled back rather than leaving partial database updates.

Together, these mechanisms help maintain consistent wallet balances when concurrent transfers occur.

🧪 Concurrency Testing

The project includes a JUnit 5 concurrency test.

The test checks wallet balances after multiple concurrent transfer operations.

The expected results are compared with the actual final balances to identify discrepancies.

The documented test scenario involves 100 concurrent transfers. In the tested scenario, the final balances matched the expected values.

Concurrency behaviour should also be tested under repeated runs, insufficient-balance conditions, and simultaneous operations involving the same wallets.

🐳 Running Locally

Prerequisites

- Java 17
- Maven or the project's Maven Wrapper
- PostgreSQL
- Git

Steps

1. Clone the repository

git clone https://github.com/utkarshswastikshree-source/paywithoutbank.git
cd paywithoutbank

2. Configure the database

Create a PostgreSQL database and configure the required connection properties in "src/main/resources/application.properties".

Use your own database URL, username, and password. Do not commit real credentials or secrets to GitHub.

3. Run the application

On Windows, use the Maven Wrapper if it is included in the repository:

mvnw.cmd spring-boot:run

Alternatively, if Maven is installed:

mvn spring-boot:run

4. Open Swagger UI

Visit:

http://localhost:8080/swagger-ui/index.html

The exact configuration requirements depend on the project's application properties.

✅ Running Tests

Run the project's tests using the Maven Wrapper on Windows:

mvnw.cmd test

Or, if Maven is installed:

mvn test

Review the test results and confirm that the expected wallet balances match the actual results.
